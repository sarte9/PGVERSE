# PG//VERSE 9 — инструкция

Это независимый игровой симулятор с вымышленными NPC, *SIM_*-паролями и коллекционными карточками. **Сайт НЕ получает доступ к Roblox и НЕ ищет настоящие утечки.** Предметы в игре не выдаются в Roblox. Изображения — созданные для проекта иллюстрации, а не официальные изображения каталога.

## Локальный запуск

1. Установите Node.js 20+ с https://nodejs.org/
2. Распакуйте архив и откройте терминал в папке `PGVERSE_v9`.
3. Запустите `npm start` (библиотеки устанавливать не нужно).
4. Откройте http://localhost:3000
5. В разделе «Мой аккаунт» зарегистрируйте профиль PG//VERSE с отдельным паролем.
6. Чтобы увидеть настоящий список пользователей, откройте «Рейтинг игроков». Второго игрока можно зарегистрировать в другом браузере/режиме инкогнито.

## Как дать доступ всем по ссылке (Render.com)

1. Создайте публичный или закрытый репозиторий GitHub и загрузите **содержимое всей папки `PGVERSE_v9`**, включая `server.js`, `package.json`, `public/`, `render.yaml`. Никогда не загружайте `data/players.json`.
2. Зарегистрируйтесь в https://render.com и подключите репозиторий GitHub.
3. Выберите **New → Blueprint** (или **New → Web Service**). Файл `render.yaml` создаст Node Web Service, примонтирует постоянный диск 1 ГБ в `/var/data` и включит `NODE_ENV=production`.
4. Подтвердите создание. **Постоянный диск и тариф Starter на Render могут быть платными.** Цены посмотрите на сайте Render перед подтверждением.
5. Когда сервис успешно запустится, Render предоставит публичный HTTPS-адрес вида `https://ваше-имя.onrender.com` — отправляйте его игрокам.
6. Домен по желанию: Render Dashboard → Settings → Custom Domains, затем пропишите DNS у регистратора.

**ВАЖНО:** если выбрать бесплатный сервис Render без постоянного диска, база в `data/players.json` может потеряться при перезапуске или публикации новой версии. Для реального сохранения требуется постоянный диск либо подключённая внешняя база данных. Этот проект рассчитан на **один серверный процесс** и один диск; не запускайте несколько экземпляров с одним JSON-хранилищем.

Для ручной настройки Web Service: **Build** `npm install`, **Start** `npm start`, переменные `DATA_DIR=/var/data` и `NODE_ENV=production`, **Disk** mount path `/var/data`.

## Что реализовано

- 36 действующих апгрейдов в категориях: скорость, шанс, экономика, склад, опыт, скип и подсказки.
- 16 разновидностей игровых NPC-аккаунтов от 2020 до мифического ADMIN//SIM 2006.
- 34 разных комбинации коллекционных предметов и 16 авторских 3D-иллюстраций популярных игровых вещей (Dominus, Valkyrie, Headless, Korblox, Shaggy и др.).
- Генератор ненастоящих логов, ручной поиск `roblox.com`, проверка вымышленных USER и PASS, пропуск NPC.
- Виртуальный маркетплейс, коллекция, квесты, четыре языка: RU, EN, ES, PL.
- Отдельная регистрация и вход с солью и scrypt-хешем пароля (пароли не хранятся открыто), HttpOnly SameSite cookies, лимит запросов.
- Автоматическое сохранение в браузере; синхронизация с сервером при авторизации.
- **Общий рейтинг настоящих пользователей** сервера, сортировка по заработанным монетам. Без сервера нет глобального рейтинга.
- Кнопка «денюшка создателю» ведёт на https://www.donationalerts.com/r/sartee_9

## Честность соревнования

Таблица рейтинга общая и настоящая, но расчёт наград пока выполняется в браузере. Это значит, что продвинутый пользователь может изменить локальное состояние и повлиять на свой счёт. Для серьёзного соревновательного проекта надо перенести генерацию NPC, начисление монет, редкости и проверку действий целиком на сервер. Также для большого числа игроков лучше заменить JSON-файл на PostgreSQL и добавить резервные копии, мониторинг и восстановление пароля.

## Безопасность

Не используйте пароль Roblox для регистрации на сайте. Не публикуйте `data/players.json` и регулярно делайте резервные копии постоянного диска. Используйте HTTPS, защищайте администраторский аккаунт хостинга и следите за обновлениями Node.js.
